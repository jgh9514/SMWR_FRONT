## 규칙: 삼항 연산자는 “단순한 선택”에만 사용한다

### 왜 필요한가 (가독성)

삼항 연산자는 짧은 조건부 값을 표현할 때는 유용하지만,

- 여러 개가 중첩되거나
- `&&`, `||` 와 섞여 복잡해지면

조건 구조를 한눈에 파악하기 어려워집니다.  
이 경우, **if 문으로 풀어서 작성하는 것이 훨씬 읽기 쉽고 안전**합니다.

---

## 코드 예시: 상태 결정 로직

### 안티 패턴 예시

```ts
const status =
  A조건 && B조건 ? "BOTH" : A조건 || B조건 ? (A조건 ? "A" : "B") : "NONE";
```

### 문제점 (냄새)

- 삼항 연산자가 **여러 단계로 중첩**되어 있어:
  - “A와 B가 모두 참이면 BOTH”
  - “A만 참이면 A”
  - “B만 참이면 B”
  - “둘 다 아니면 NONE”
  라는 간단한 규칙을, 직접 해석해서 머릿속으로 다시 조합해야 합니다.
- 괄호 배치가 살짝만 바뀌어도 의미가 달라질 수 있어,
  - 유지보수 시 버그를 심기 쉬운 형태입니다.

---

## 개선안: if 문으로 풀어서 작성하기

```ts
const status = (() => {
  if (A조건 && B조건) return "BOTH";
  if (A조건) return "A";
  if (B조건) return "B";
  return "NONE";
})();
```

- 위에서 아래로 읽으면서:
  - “둘 다 참이면 BOTH”
  - “그렇지 않고 A만 참이면 A”
  - “그렇지 않고 B만 참이면 B”
  - “그 외에는 NONE”
  이라는 규칙을 그대로 따라갈 수 있습니다.
- 로직을 변경하거나 케이스를 추가할 때도:
  - if 블록 하나를 추가/수정하면 되므로 실수가 줄어듭니다.

---

## 이 프로젝트에서의 적용 원칙

### 1. 삼항 연산자 사용 기준

삼항을 써도 좋은 경우:

- **아주 단순한 선택**일 때

```tsx
const label = isError ? "에러" : "정상";
const color = isActive ? colors.blue500 : colors.grey500;

return <Button disabled={!canSubmit}>{canSubmit ? "제출" : "제출 불가"}</Button>;
```

- 한 줄 안에서 “값 두 개 중 하나를 선택”하는 정도의 단순 로직

삼항 대신 if로 풀어야 하는 경우:

- 삼항이 **두 번 이상 중첩**되는 경우
- 삼항 안에 또 다른 삼항/논리 연산자(`&&`, `||`, `!`)가 들어가는 경우
- 읽으면서 “괄호를 한 번 더 확인하게 되는” 순간이 생기는 경우

### 2. JSX 안에서는 읽기 좋은 형태 우선

복잡한 삼항을 JSX 안에서 직접 쓰지 말고,

```tsx
// 안티 패턴
return isA ? <AView /> : isB ? <BView /> : <DefaultView />;
```

다음과 같이 **미리 분기**하거나, 전용 컴포넌트를 사용합니다.

```tsx
// 권장
if (isA) {
  return <AView />;
}
if (isB) {
  return <BView />;
}
return <DefaultView />;
```

또는:

```tsx
return <PageContent status={status} />;
```

처럼 상위에서는 간단한 값만 넘기고, 상세 분기는 하위 컴포넌트에서 처리하도록 합니다.

### 3. 리팩터링 시 체크 포인트

- 삼항 표현식을 볼 때마다 스스로 물어봅니다.
  - “**조건 구조가 한눈에 보이는가?**”
  - “이걸 if 문으로 풀면 더 이해하기 쉬울까?”
- “한 줄에 억지로 넣은 느낌”이 든다면:
  - 과감히 즉시 실행 함수(`(() => { ... })()`) 또는 별도 함수로 빼고
  - if/return 구조로 명시적으로 작성합니다.

이 원칙을 지키면, 삼항 연산자는 “짧고 단순한 선택”에만 쓰이고,  
복잡한 분기 로직은 항상 **읽기 쉬운 if 구조**로 드러나게 되어 전체 코드의 가독성이 좋아집니다.
